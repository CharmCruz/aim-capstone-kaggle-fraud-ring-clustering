Identifying Fraud Rings Through Clustering¶

Technical Walkthrough¶

Problem: Can transactions be grouped into clusters that concentrate fraudulent activity and may indicate coordinated behaviour?

The clustering algorithms did not use isFraud in their distance calculations or model fitting. Historical fraud labels were used for supervised feature selection, post-hoc cluster assessment, and validation.

Approach: K-Means, DBSCAN, and Hierarchical Clustering were compared using internal metrics and a holdout-oriented robustness check.

Dataset Overview¶

What was done: Loaded and joined the raw Vesta transaction and identity tables. Profiled dataset size, fraud rate, data types, missingness, and key numeric variables before cleaning.

Key result: The dataset contains 590,540 transactions with a 3.50% fraud rate and substantial missing identity information.

Cleaning and Feature Engineering¶

What was done:

  • Created has_identity_data before dropping sparse identity fields.
  • Checked for duplicate rows.
  • Removed columns with more than 90% missingness.
  • Created domain-derived features such as log amount, email-domain matching, frequency features, and time buckets.

Feature pipeline:

434 raw columns → 435 after missingness flag → 424 after sparse-column removal → 462 after feature engineering → 271 selected features → 102 PCA components

Missingness was retained where it could carry fraud-related signal.

Applied EDA: Correlation and Clustering Tendency¶

What was done: Examined feature relationships and tested clustering tendency using the Hopkins statistic across five random seeds.

Result: Hopkins averaged 0.974, with a range of 0.970–0.982.

This indicates strong non-random structure suitable for clustering. It does not, by itself, prove that the clusters represent fraud rings.

Feature Selection and Dimensionality Reduction¶

What was done:

  • Used Random Forest importance to identify informative variables.
  • Applied variance and correlation filtering.
  • Reduced the selected feature set using PCA.
  • Used t-SNE on a 20,000-row sample for visual exploration.

Result:

  • 462 engineered features reduced to 271 selected features.
  • PCA retained 90% of variance using 102 components.
  • t-SNE showed multiple local structures rather than one uniform data cloud.

Feature selection used historical fraud labels, so the overall pipeline is label-informed even though the clustering fit itself was unsupervised.

PCA: 271 features -> 102 components (90% variance retained)

Model Results: K-Means, DBSCAN, and Hierarchical¶

What was done: Tested three clustering approaches and assessed fraud concentration against the sample baseline.

Configurations:

  • K-Means: k=5; 20,000-row sample
  • DBSCAN: eps=18.26; min_samples=10; 10,000-row sample
  • Hierarchical: Ward linkage; k=3; 2,000-row sample

Result: The notebook outputs below show the tested cluster counts, fraud rates, cluster sizes, and DBSCAN internal metrics.

Candidate settings were selected using fraud concentration after clustering, so this comparison is exploratory rather than fully label-free.

Holdout-Oriented Validation: K-Means and DBSCAN¶

What was done: Refit K-Means and DBSCAN on 80% of their respective samples and evaluated fraud concentration on the remaining 20%.

Interpretation:

  • K-Means declined from 15.3× exploratory concentration to approximately 3.2× on holdout data.
  • DBSCAN remained concentrated at approximately 9.9× baseline on the holdout data.
  • K-Means had higher recall; DBSCAN had higher precision.

Caveat: This is a holdout-oriented robustness check, not fully leakage-free production validation. Preprocessing was shared before splitting, and DBSCAN holdout labels were assigned using a KNN proxy.

  • Compared the K-Means high-risk cluster with the remaining sample.

Technical Findings and Conclusion¶

Output summary:

Method Exploratory result Holdout result
K-Means 15.3× baseline 3.22× baseline
DBSCAN 8.45× baseline 9.94× baseline
Hierarchical 2.9× baseline Not holdout-tested

Findings:

  • All three methods found fraud-concentrated groups.
  • K-Means produced the highest exploratory concentration but declined substantially on holdout data.
  • DBSCAN had the strongest internal metrics and remained the strongest candidate in the holdout-oriented check.
  • The high-risk cluster was associated mainly with product and device-data patterns.
  • The proxy fairness audit showed uneven flagging across anonymous regions.

Recommendation: Combine K-Means as the higher-recall candidate generator with DBSCAN as a precision-oriented filter, then recalibrate thresholds by subgroup before production deployment.
